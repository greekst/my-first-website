## Problem Statement
The Design, Build, and Publish cards explain the three stages but feel static. This site is a practice project for learning Codex, gstack, Git, GitHub, and simple web code. The cards should make each stage something a visitor can try.

## What Makes This Cool
Each card acts out its own idea. The visitor sees a tiny visual story, then discovers one useful lesson. Replaying a scene makes the relationship between the animation and the lesson clear.

## Constraints
- Keep the existing one-page layout, colorful playful style, three-file structure, and working color button.
- Use the existing HTML, CSS, and JavaScript; add no library or external service.
- Work with mouse, touch, and keyboard, including a narrow phone screen.
- Make the lesson available when motion is reduced or JavaScript is unavailable.

## Premises
- The problem is the cards' lack of interaction, so focus on the cards rather than redesigning the page.
- Each scene should teach the stage it represents. Extra movement without a lesson would miss the learning goal.
- The project log records a successful GitHub Pages deployment, but the site files do not prove the current Pages setting. Check that setting before publishing the change.

## Approaches Considered
- Quick reveal: one shape moves and a lesson appears. Simpler, but the stages would feel too similar.
- Mini-scenes: distinct Design, Build, and Publish sequences, each ending with a lesson. Chosen because it makes the three stages memorable.

## Recommended Approach
Add one button inside each card when JavaScript initializes, initially labeled “Remix design”, “Assemble page”, or “Launch site” for its stage. On activation, play a roughly 1–2 second scene and reveal its lesson; afterward label the button "Replay". Keep a card's lesson visible when replaying. During playback, label the button “Restart”; a second press restarts that card's scene. Cards work independently.

- **Design / Remix:** show one small layout first in a warm palette, then in a contrasting cool palette; keep its layout fixed so the color-driven mood change is clear. Shapes support the comparison, then reveal: “Small color choices can change the whole mood.”
- **Build / Assemble:** HTML, CSS, and JS pieces snap into a small page, then reveal: “HTML adds structure, CSS adds style, and JavaScript adds behavior.”
- **Publish / Launch:** show three labeled visual beats in order: Git saves a version, the project is pushed to GitHub, and GitHub Pages serves the site at a URL; then reveal: “Git saves versions; GitHub Pages puts the site online.”

Below the three cards, add one compact reflection prompt: “Your turn: What do HTML, CSS, JavaScript, Git, and GitHub Pages each do?” The prompt asks for thought, not typed input, and sits before the closing section.

Use native buttons with visible focus. Treat animated shapes as decoration. Render each lesson visibly in the HTML by default. Only after JavaScript initializes the cards should it show the scene buttons and hide lessons that have not yet been revealed. If JavaScript is unavailable, visitors see every lesson and no inactive scene buttons. On a first reveal, announce the lesson through a polite live region; replay leaves the visible lesson in place and does not announce it again. With reduced-motion preference, show the lesson immediately when a button is activated and skip the moving sequence.

## Card Layout and States
Each existing large icon becomes the scene area. Reading order in every card: step number → scene → heading → current short description → action button → revealed lesson. Keep the scene area bounded and the lesson below the button so replay never moves or hides a lesson already read. On a phone, the cards remain one column; card height grows naturally when a lesson appears rather than clipping it. Buttons have at least a 44px touch target and use the existing dark outline and focus treatment.

```text
Page hero and color button
  ↓ Explore the process
Three steps: Design | Build | Publish (one column on phones)
  Each card: number → mini-scene → heading → description → button → lesson
  ↓
Your turn: explain the five tools
  ↓
Existing closing and footer
```

| Card state | What a visitor sees |
| --- | --- |
| No JavaScript | All three lessons visible; no inert scene buttons. |
| Ready | Scene at its first frame, stage-specific action button, lesson hidden after initialization. |
| Playing | Scene advances for about 1–2 seconds; button says “Restart” and remains usable. |
| Revealed | Final scene frame holds, lesson appears, button says “Replay”; first reveal is announced politely to a screen reader. |
| Replay | Scene runs again; the already-visible lesson stays in place and is not announced again. |
| Reduced motion | The lesson appears immediately on activation, with no moving sequence. |

The site uses existing palette variables, rounded bold type, dark borders, and offset shadows. Scene labels are short, high contrast, and visible without relying on color alone. Keep the three card colors distinct in every page palette. The Design scene changes only the small composition's colors so the before/after comparison is clear; Build and Publish use separate, labeled pieces rather than generic flying shapes.
